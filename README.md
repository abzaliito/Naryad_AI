# НарядAI

Веб-приложение для выдачи и контроля производственных нарядов. Решение кейса АО «Костанайские минералы» для Qostanai Industry Hackathon 2026: мастер выдаёт задание, исполнитель сдаёт отчёт с фотографиями, ИИ проверяет результат, мастер принимает работу.

Адаптивная PWA для компьютера и телефона. Интерфейс RU / ҚАЗ; производственные названия и пользовательские отчёты сохраняют исходный язык. Часовой пояс — `Asia/Qyzylorda`, смены 08:00–20:00 и 20:00–08:00.

## Запуск одной командой

Нужен запущенный Docker Desktop с Linux containers или Docker Engine с Compose. Из папки проекта:

```sh
docker compose up --build
```

Откройте **[localhost:3001](http://localhost:3001)**. Учебная база создаётся автоматически. Без ключа API доступны приложение, аналитика и явно обозначенная проверка правил; для настоящего ИИ настройте подключение ниже.

| Действие | Команда |
|---|---|
| Запустить в фоне / обновить исходники | `docker compose up -d --build` |
| Применить изменения `.env` | `docker compose up -d` |
| Посмотреть журнал сервера | `docker compose logs -f app` |
| Остановить, сохранив данные | `docker compose down` |

Наряды, фотографии и настройки сохраняются в томе `naryad_data`. Не используйте `down -v`, если данные нужны. Локальная папка `data/` при разработке и том Docker — отдельные базы. Если порт занят, задайте `APP_PORT=3080` в `.env`.

## Аккаунты для проверки

| Роль | Логин | PIN | Возможности |
|---|---|---|---|
| Мастер | `master` | `1234` | Выдача, контроль, переназначение и приёмка |
| Исполнитель | `worker` | `1234` | Свои наряды, очередь, отчёты и оценки |
| Дополнительный исполнитель | `worker9` | `1234` | Проверка нового задания с другого устройства |

Также доступны `master2` и `worker2`…`worker15`. Данные вымышлены: более 550 нарядов за три месяца, 4 участка, более 25 машин, 15 рабочих, 3 бригады, шифры и материалы. Архив создаётся один раз и не сдвигается при перезапуске.

## Возможности

- **Наряды:** участок и оборудование, плановая/внеплановая работа, приоритет, срок, норматив, ответственный/бригада, фото до/после, работы и расход ТМЦ. Быстрые шаблоны, подбор исполнителя по специальности, загрузке и рейтингу, подсказки шифра и норматива.
- **Полный цикл:** выдача → принятие или очередь → работа → исполнение → проверка ИИ → приёмка мастером. Очередь сохраняет порядок постановки (FIFO). Отказ и пауза требуют причины; доработка возвращает работу исполнителю. История попыток сохраняется. Два наряда одновременно выполнять нельзя.
- **Контроль:** напоминание за 30 минут, просрочка мастеру и исполнителю, эскалация отсутствия ответа через 10 минут или 3 минуты для аварийного наряда. Web Push, SSE и серверный контроль при закрытой вкладке.
- **Проверка качества:** соответствие работ заданию, комплектность, материалы и сроки, сравнение фото, поиск повторных снимков, оценка 1–5, объяснения и уверенность. Окончательное решение и изменение оценки — за мастером.
- **Журнал действий:** автор, время, изменения, фильтры и переход в наряд; история оборудования. Права проверяются сервером; исполнитель работает только со своими нарядами.
- **Аналитика:** смена и произвольный период, рейтинги сотрудников/бригад, материалы, расчётный простой, повторные отказы, отказы после ППР и раннее предупреждение роста неисправностей. Исходные записи и рекомендации, еженедельная сводка, Excel, печать в PDF.
- **Телефон:** последовательность «принять → начать → исполнить» и отчёт с фото сохраняются без сети и синхронизируются после восстановления связи. Журнал различает время действия на устройстве и приёма сервером; при неверных часах отчёт сохраняется с серверным временем и пометкой. QR оборудования, голосовой ввод при поддержке браузера, установка PWA, RU / ҚАЗ.

В учебных нарядах заложены повторы на конвейере К-3, повышенный расход масла, отказы после обслуживания и доработки. Выводы рассчитываются из записей; статистическая связь не доказывает причину поломки или вину сотрудника. Раннее предупреждение — объяснимый сигнал риска.

Рейтинг: **качество 40 + сроки 25 + приёмка без доработок/повторов 20 + объём/сложность 10 + обоснованность отказов 5**. Оценка мастера приоритетна. Повтор за 7 дней относится к предыдущему ремонту; объём сравнивается внутри выборки. Простой объединяет интервалы нарядов, без телеметрии. Выдача считается по дате выдачи, исполнение — по сдаче, приёмка/рейтинг — по закрытию: ноль в новой смене без действий корректен.

## Подключение GPT‑5 mini

Создайте `.env` по [.env.example](.env.example), сохранив уже имеющиеся настройки:

```dotenv
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-5-mini
AI_API_KEY=ваш_ключ_API
AI_SEND_PHOTOS=true
```

Примените: `docker compose up -d`. Ключ хранится только на сервере; `.env` исключён из Git и Docker-образа. На другом стенде ключ добавляется отдельно. Можно указать другой совместимый `/v1` API; локальная модель из Docker доступна через `http://host.docker.internal:11434/v1`.

`AI_SEND_PHOTOS=true` разрешает передачу до пяти фото «до» и пяти «после» провайдеру. Кнопка **«Скрыть данные»** позволяет закрасить лица, бейджи и документы на устройстве перед загрузкой. EXIF удаляется; известные имена, логины, телефоны и email фильтруются из текста. Автоматического распознавания личных данных на фото нет; используйте разрешённые снимки. Фото не подтверждают скрытые операции и не разрешают эксплуатацию оборудования.

Уверенность ниже 60% требует ручной проверки. При ошибке API или лимите отчёт явно обозначает локальные правила; они не распознают качество ремонта. Успешный вызов возвращает `provider: configured-model`; `/api/health` показывает только наличие настроек. Ассистент поясняет рассчитанные сервером факты и не меняет наряды.

| Настройка | По умолчанию |
|---|---:|
| `AI_DAILY_REQUEST_LIMIT` — все попытки запросов за сутки UTC | 150 |
| `AI_USER_HOURLY_LIMIT` — вопросы ассистенту на пользователя за час | 20 |
| `AI_ASSISTANT_MAX_TOKENS` — выходные токены ответа | 1200 |
| `AI_REVIEW_MAX_TOKENS` — выходные токены проверки | 3000 |

Максимум два одновременных обращения; счётчики сохраняются при перезапуске. Ошибки API автоматически не повторяются. Страницы, графики и напоминания API не расходуют; старые оценки не пересчитываются. Это ограничения использования, а не денежный потолок. Расход проверяйте в кабинете провайдера.

## Railway

1. Подключите GitHub-репозиторий как сервис — корневой `Dockerfile` собирает интерфейс и API вместе.
2. Добавьте постоянный **Volume** с путём `/app/data`. Оставьте **одну реплику**: SQLite и фото находятся на этом диске.
3. Задайте Variables: `DATA_DIR=/app/data`, `HOST=0.0.0.0`, `PORT=3001`, `RAILWAY_RUN_UID=0` для доступа к тому, `COOKIE_SECURE=true`, свой `VAPID_SUBJECT=mailto:ваша-почта` и настройки ИИ выше.
4. Создайте публичный HTTPS-домен с целевым портом `3001`, задайте `APP_ORIGIN=https://ваш-домен` без завершающего `/` и примените настройки. Healthcheck — `/api/health`.
5. Войдите с телефонов под разными ролями и разрешите уведомления. QR создавайте с публичного адреса.

Railway даёт новым аккаунтам пробные $5 на срок до 30 дней, затем Free с $1 ресурсов в месяц. Это не безлимитное бесплатное размещение; Limited Trial может ограничивать исходящую сеть. Официальные условия: [Free Trial](https://docs.railway.com/pricing/free-trial), [тарифы](https://docs.railway.com/pricing), [Volume и права](https://docs.railway.com/volumes).

По Wi-Fi интерфейс можно открыть на `http://<IPv4-компьютера>:3001`; адрес показывает `ipconfig`. `localhost` на телефоне означает сам телефон. Полноценные PWA и push требуют доверенного HTTPS.

## Архитектура и разработка

React 19 + TypeScript + Vite, Node.js 24 + Express, SQLite WAL, JPEG, Web Push, SSE. Один сервер обслуживает интерфейс и API. Авторизация — HttpOnly-cookie; версии нарядов защищают от перезаписи устаревшим клиентом, идемпотентность — от повторной отправки.

| Путь | Назначение |
|---|---|
| `src/` | Интерфейс, расчёты, локализация и офлайн-хранение |
| `server/` | API, доступ, база, ИИ, уведомления и генератор данных |
| `public/` | Manifest, Service Worker и иконки PWA |
| `Dockerfile`, `compose.yaml` | Сборка, запуск и постоянный том |

Основные API: `/api/auth/login`, `/api/bootstrap`, `/api/orders`, `/api/orders/:id/transition`, `/api/orders/:id/complete`, `/api/orders/:id/review`, `/api/uploads`, `/api/audit`, `/api/assistant`, `/api/reports/export`. Изменения требуют авторизации и разрешённой роли; ошибки возвращают `{error: string}`.

Без Docker нужны Node.js 24+ и npm:

```sh
npm ci
npm run dev
```

Разработка: [localhost:5173](http://localhost:5173), API: `3001`. Сборка с проверкой TypeScript: `npm run build`; запуск собранной версии: `npm start`. Если Docker занимает `3001`, сначала остановите его.

## Проверка решения

Мастером выдайте наряд; исполнителем примите, начните и сдайте работы, материалы и фото; мастером откройте заключение ИИ и примите либо верните на доработку. Проверьте «Журнал действий», отчёт и рейтинг. Для офлайн-сценария сначала откройте PWA с сетью, затем отключите её и после действий восстановите связь.

| Критерий кейса | Баллы | Что показывать |
|---|---:|---|
| Работающий MVP | 25 | Цикл на разных устройствах, очередь, уведомления, доработка, журнал |
| Качество ИИ | 25 | Правильный/ошибочный отчёт, фото до/после, уверенность, решение мастера |
| Аналитика | 15 | Рейтинг, материалы, простой, закономерности и исходные записи |
| Удобство | 15 | Мобильные формы, голос, QR и восстановление связи |
| Применимость | 10 | Роли, сохранность данных, расчёты и архитектура |
| Презентация и демо | 10 | Ссылки/аккаунты, до 10 слайдов, живое демо около 7 минут, видео до 3 минут |

После публикации на физических телефонах нужно подтвердить фоновый push и измерить выдачу ≤1 минуты/6 нажатий, статус ≤5 секунд, фото ≤10 секунд. Настоящая модель проверена на синтетических текстах и изображениях; качество на производственных снимках требует отдельной выборки. Казахскую терминологию следует вычитать с носителем. Наличие функций не гарантирует оценку жюри.

Резервируйте **весь том**, включая базу и фото, и проверяйте восстановление. SQLite рассчитана на один экземпляр прототипа; для масштабирования нужны общая СУБД, объектное хранилище, очередь задач и согласованные интеграции ERP/1С/ТОиР. Перед эксплуатацией замените учебные аккаунты.
