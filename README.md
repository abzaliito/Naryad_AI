# НарядAI

Рабочий прототип системы выдачи и контроля производственных нарядов для кейса АО «Костанайские минералы», Qostanai Industry Hackathon 2026.

**Наряд выдан — ИИ на контроле.** Мастер выдаёт задание, исполнитель фиксирует работу, система проверяет подтверждения, мастер принимает результат. Интерфейс и время смены — на русском языке, часовой пояс `Asia/Qyzylorda`.

В комплекте: React PWA, сервер Express, локальная SQLite, справочники, синтетическая история больше 550 нарядов за три месяца, тесты, сценарий защиты и презентация. Дизайн и организация карточек учитывают предоставленные проекты `sis_icore` / `sis_front`; исходные проекты не изменялись.

## Быстрый запуск

Установите и запустите **Docker Desktop** в режиме Linux containers (либо Docker Engine с Compose). В терминале из папки проекта выполните:

```powershell
docker compose up --build
```

Откройте [http://localhost:3001](http://localhost:3001). Docker соберёт интерфейс, запустит сервер и при первом запуске создаст учебную базу. Node.js на компьютере и настройка `.env` не требуются. При первом запуске также достаточно `docker compose up`; флаг `--build` пересобирает приложение после изменений исходников.

Для работы в фоне: `docker compose up -d --build`. Логи: `docker compose logs -f app`. Остановка: `docker compose down`. Наряды, фото и ключи уведомлений сохраняются в томе **`naryad_data`** при остановке и пересоздании контейнера.

Если порт `3001` занят, добавьте `APP_PORT=3080` в `.env` и повторите запуск — приложение откроется на `http://localhost:3080`. Остальные настройки необязательны; примеры есть в [.env.example](.env.example). После изменения `.env` выполните `docker compose up -d`.

Контейнер использует собственный том данных. Существующая локальная папка `data/` сохраняется отдельно и автоматически в Docker не переносится. Для первой сборки нужен доступ к интернету для загрузки образа Node.js и npm-зависимостей.

## Локальная разработка без Docker

Требуется **Node.js 24+** и npm.

```powershell
npm ci
npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173). API работает на порту `3001`; Vite проксирует `/api` и `/uploads`. При первом запуске сервер создаёт базу и загружает учебные данные. Последующие запуски сохраняют внесённые изменения.

Для изменения настроек скопируйте `.env.example` в `.env`. Если Docker уже занимает порт `3001`, сначала остановите контейнер командой `docker compose down`.

Для запуска собранной версии:

```powershell
npm run build
npm start
```

Приложение и API будут доступны на [http://localhost:3001](http://localhost:3001). `npm run build` проверяет TypeScript и создаёт `dist/`. Список основных переменных окружения есть в [.env.example](.env.example).

## Демо-аккаунты

| Роль | Логин | PIN | Доступ |
|---|---|---|---|
| Мастер смены | `master` | `1234` | Выдача, переназначение, приёмка, отчёты |
| Исполнитель | `worker` | `1234` | Собственные наряды, очередь, отчёты |
| Другой исполнитель | `worker9` | `1234` | Удобен для нового задания в демо |
| Руководитель | `manager` | `1234` | Обзор, аналитика, отчёты |
| Администратор | `admin` | `1234` | Справочники и настройки |

Дополнительно доступны `master2` и `worker2`…`worker15` с тем же учебным PIN. Аккаунты и данные вымышлены. Перед эксплуатацией замените демо-учётные записи; готового контура кадрового учёта или интеграции с ERP здесь нет.

## Что реализовано

- Выдача с участком, оборудованием, типом, приоритетом, исполнителем, сроком, нормативом, описанием и фото; канбан, списки и история изменений.
- Роли проверяются на сервере. Исполнитель меняет только свои наряды. Начать второй наряд параллельно уже выполняемому нельзя.
- Полный рабочий цикл: принятие, очередь, отказ с причиной, начало, пауза с причиной, отчёт, проверка, доработка и приёмка мастером.
- SSE и резервное обновление данных, уведомления внутри приложения, подписка на Web Push. Контроль сроков продолжает работать на сервере при закрытой вкладке.
- Фото до/после, сжатие в браузере и серверная обработка изображений; загрузки доступны по авторизации. После повторного исполнения или переназначения предыдущие отчёты, проверки и фото сохраняются в истории попыток.
- Сводка смены, рейтинги сотрудников и бригад, динамика, расход материалов, история и расчётные простои оборудования, статистические сигналы повторных неисправностей.
- Выгрузка `.xlsx` с нарядами, работами, проверками, событиями, рейтингами, расходом ТМЦ и расчётным простоем; печать средствами браузера, справочники, статистический ассистент мастера. PDF из карточки включает задание, отчёт, фото, проверки, прежние попытки и полную хронологию независимо от открытой вкладки.
- Администратор добавляет и редактирует записи справочников в интерфейсе, в том числе признак смены, логин и PIN. Изменение PIN или роли завершает сессии соответствующего сотрудника.
- Сохранение последнего снимка данных и отложенных переходов статуса при потере сети. Загрузка фото и полноценное завершение наряда требуют связи.

Подробная сверка с кейсом и ограничения: [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md).

## Проверка качества и подключение модели

Без ключей система работает в режиме **`demo-rules`**. Проверяет заполнение работ и шифра, наличие фото, точные повторения файлов, заявленное время снимка, срок и превышение расхода материалов. Это воспроизводимая проверка правил, которая **не распознаёт визуальное качество ремонта и не заменяет языковую модель**. Исторические оценки в тестовом наборе синтетические.

Для языковой или мультимодальной модели настройте в `.env`:

```dotenv
AI_BASE_URL=http://host.docker.internal:11434/v1
AI_MODEL=имя-установленной-совместимой-модели
AI_API_KEY=
AI_SEND_PHOTOS=false
```

Этот адрес позволяет приложению в Docker обратиться к модели на компьютере. Сервер модели должен принимать соединения со стороны Docker. При локальном запуске через npm используйте `http://127.0.0.1:11434/v1`; внутри контейнера `127.0.0.1` означает сам контейнер. Для модели на другом сервере укажите её доступный адрес. После изменения настроек пересоздайте контейнер: `docker compose up -d`.

Нужен сервер, поддерживающий `POST /chat/completions` и JSON-ответ; для сравнения фото также нужна поддержка `image_url`. Модель не скачивается автоматически. Локальный Ollama или другой совместимый сервер можно подключить по этому контракту, но конкретную модель необходимо отдельно установить и проверить. Приложение не зависит от конкретного внешнего провайдера.

На текстовый анализ передаётся ограниченный набор полей. Из текста удаляются известные имена, логины, адреса почты и телефоны; идентификаторы сотрудников и произвольные комментарии не включаются в запрос. Это базовая фильтрация, а не гарантия полного обезличивания любого произвольного текста. Фото по умолчанию не отправляются; `AI_SEND_PHOTOS=true` явно разрешает передачу. EXIF удаляется, однако лица и надписи в пикселях автоматически не скрываются. Для реальных производственных данных предпочтителен проверенный локальный контур.

Если модель недоступна или вернула неверный формат, отчёт явно сообщает о переходе на локальные правила. Модель не может отменить отсутствие обязательных подтверждений. **Окончательное закрытие всегда выполняет мастер.**

## Телефоны и уведомления

Для проверки нескольких устройств подключите телефоны и компьютер к одной сети. Откройте `http://<локальный-IP-компьютера>:3001` (либо порт из `APP_PORT`), добавив этот точный origin в `APP_ORIGIN`, и разрешите доступ к порту в настройках локальной сети. После изменения `.env` выполните `docker compose up -d`. При разработке через Vite используется порт `5173`. Это позволяет проверить работу ролей и мгновенные обновления; обычный LAN HTTP не включает фоновые Web Push и установку PWA во всех браузерах.

Для полноценного PWA/push на телефоне нужен **HTTPS с доверенным устройству сертификатом**, единый origin интерфейса и API и доступ сервера к push-службе браузера. Укажите этот origin в `.env`, установите `COOKIE_SECURE=true`, затем разрешите уведомления кнопкой приложения. VAPID-ключи создаются автоматически и хранятся вместе с базой; после их замены устройства необходимо подписать заново.

На Android используйте совместимый браузер с поддержкой Service Worker и Web Push. Фактическая доставка, звук и задержка зависят от разрешений ОС, режима энергосбережения и браузера. Требования ≤5 секунд для изменения статуса и ≤10 секунд для загрузки фото необходимо отдельно измерить на целевых телефонах и сети; аппаратная проверка не заменяется локальными тестами.

## Данные, рейтинг и аналитика

`server/seed.mjs` генерирует справочники, архив и активную смену относительно первого запуска. Повторные отказы конвейера К-3, повышенное списание масла, отказы после ППР и возвраты на доработку заложены в **сами наряды**, а выводы рассчитываются из записей.

Рейтинг состоит из 100 баллов: **качество 40 + сроки 25 + приёмка без доработок/повторных отказов 20 + объём и сложность 10 + обоснованность отказов 5**. Оценка мастера имеет приоритет над оценкой ИИ. Повтор неисправности на том же оборудовании за 7 дней относится к предшествующему ремонту. Объём нормируется к лучшему показателю выбранной группы. Для сотрудников без закрытых нарядов оценка не рассчитана. Формула и составляющие доступны в интерфейсе и `src/domain.ts`.

Рейтинг зависит от доступной выборки: исполнитель видит только собственные наряды, поэтому личный расчёт не является местом в общей таблице предприятия и может отличаться от сравнения всех сотрудников у мастера. Для сравнения бригад используйте роль мастера или руководителя с одинаковыми фильтрами и периодом.

Список нарядов и расход ТМЦ отбираются по дате выдачи, рейтинг — по дате закрытия. Счётчики исполнения и приёмки используют соответствующие даты событий: работа, выданная вчера и исполненная сегодня, входит в сегодняшнее исполнение. Начало периода включается, конец исключается. Это разные показатели, поэтому число исполнений за смену может превышать число выданных за неё нарядов.

Простой оценивается по интервалам нарядов; пересекающиеся интервалы одной машины объединяются. Учитывается только пересечение интервала ремонта с выбранным периодом, включая начавшиеся ранее ремонты. Плановые и внеплановые интервалы также объединяются по отдельности; при их пересечении сумма этих двух колонок может превышать общий простой. Это **расчётный простой**, не телеметрия оборудования. Статистические сигналы показывают совпадения и рекомендации, а не доказанную причину неисправности или надёжный прогноз отказа.

В Docker база и фотографии находятся в `/app/data` внутри постоянного тома `naryad_data`. Команда `docker compose down` оставляет том на месте; удаление тома удаляет сохранённые наряды и фото. Для резервного копирования остановите приложение и сохраните весь каталог `/app/data` из контейнера либо содержимое тома, включая SQLite и фотографии.

При локальном запуске база находится в `data/naryad.sqlite`, фотографии — в `data/uploads`; расположение меняет `DATA_DIR`. Для новой независимой локальной демонстрации укажите новую пустую папку `DATA_DIR`; старая база сохранится. Для резервного копирования остановите сервер и сохраните весь каталог данных. Не публикуйте `.env` и рабочую базу в репозиторий.

## Проверка и материалы для защиты

```powershell
npm test
npm run build
npm run test:e2e
```

В среде, запрещающей запуск дочерних процессов тестовым раннером:

```powershell
node --test --test-isolation=none tests/*.test.mjs
```

Доменная проверка отдельно: `node --test --test-isolation=none tests/domain.test.mjs`. Она проверяет границы смен, остановку просрочки после исполнения, формулу рейтинга, повторные отказы, фильтры отчётов, переходящие наряды, очередь, пересечение простоев и обнаружение закономерностей тестовой истории.

Браузерные тесты запускаются после сборки на отдельном сервере и временной базе; рабочую базу они не изменяют. На Windows используется установленный Microsoft Edge, если он найден. В другой среде установите Chromium для Playwright либо укажите путь к совместимому браузеру в `PLAYWRIGHT_EXECUTABLE_PATH`. Отчёт сохраняется в `playwright-report/`; скриншоты и трассировки ошибок — в `test-results/`. Эмуляция телефона проверяет интерфейс, но не подтверждает доставку push на физический Android.
